# PyReps — Architecture

## Decisions at a glance
| Concern | Choice | Why |
|---|---|---|
| App type | Static, offline-first PWA | Free to host and install on iPhone; no Apple developer account |
| Framework | Vite + React + TypeScript (strict) | No server is needed, so Next.js adds nothing here; Vite + `vite-plugin-pwa` is the most direct path to a solid offline PWA |
| Styling / UI | Tailwind CSS + a few shadcn/ui primitives (Button, Dialog, Sheet, Progress) | Bati's usual stack; small bundle |
| State | Zustand (UI and session state) + Dexie (IndexedDB persistence) | Zustand is Bati's usual choice; Dexie makes IndexedDB queries simple |
| Python runtime | Pyodide (real CPython in WebAssembly), **self-hosted** from the npm package, running in a **Web Worker** | Exact Python semantics (predict-the-output must match CPython), offline, kill-able on infinite loops |
| Scheduling | `ts-fsrs` (FSRS algorithm, MIT) | Current best open-source spaced-repetition scheduler |
| Content | YAML files in `content/`, validated by Zod (shape) and by a CPython script (answers) | Content is reviewable in Git, and wrong answers can't ship |
| Tests | Vitest (unit), Playwright with an iPhone device profile (e2e), `scripts/validate_content.py` (content) | |
| Hosting | GitHub Pages via GitHub Actions | Free and HTTPS (needed for service workers) |

Check current stable versions with `npm view <pkg> version` before installing, and pin exact versions. At the time of writing, Pyodide is published as `314.x` (Python 3.14), along with ts-fsrs 5.x, Dexie 4.x, vite-plugin-pwa 2.x, Tailwind 4.x, Zod 4.x and Vite 8.x. Adapt the config syntax to whatever major versions you actually install.

## Screens and navigation
A bottom tab bar (respecting `env(safe-area-inset-bottom)`) with **Today · Topics · Projects · Playground · Stats**. Settings opens from Today.
- **Today**: due count, new count, streak, a big "Start today's reps" button, and "Python ready ●" status.
- **Session**: a full-screen card player with a progress bar and a close button (progress is saved per card). It ends with a summary: right/wrong per topic, next due counts.
- **Topics**: the 12 core topics, then the 6 domain decks, with mastery bars. Tap one for "Practise 10" and a card list (with previews).
- **Projects**: a list of projects with step progress. The project view shows the step card, file tabs, Run, and Export file.
- **Playground**: free editor plus output. It has the `data/` files and `voicelab`, and keeps the last code.
- **Stats**: streak calendar (last 8 weeks), 7-day pass rate, reviews per day, cards by state.
- **Settings**: new cards per day, max reviews, unlocked topics (checkboxes for course modules), font size, export/import backup, reset progress, about/licences.

## Content model (`src/content/schema.ts`)
CONTENT.md has the authoring rules and examples. These are the TypeScript shapes (generated from Zod):
```ts
type Topic = { id: TopicId; title: string; module: number; order: number };
type Base = { id: string; topic: TopicId; level: 1 | 2 | 3; prompt: string; explain: string; tags?: string[] };
type PredictCard = Base & { type: "predict"; code: string; answer: string; options?: string[] };       // exact stdout
type McqCard     = Base & { type: "mcq"; code?: string; options: string[]; correct: number };
type FillCard    = Base & { type: "fill"; code: string; blanks: { answer: string; options: string[] }[]; expected_output?: string };
type SpotBugCard = Base & { type: "spot_bug"; code: string; bug_line: number; fixed_code: string; expected_output?: string };
type ParsonsCard = Base & { type: "parsons"; lines: string[]; distractors?: string[]; setup?: string; expected_output?: string };
type WriteCard   = Base & { type: "write"; starter: string; tests: string; hint: string; solution: string };
type Card = PredictCard | McqCard | FillCard | SpotBugCard | ParsonsCard | WriteCard;
type Project = { id: string; title: string; summary: string; files: Record<string, string>; steps: WriteCard[] };
```
`scripts/build_content.ts` reads YAML, validates with Zod (unique ids, `bug_line` in range, blanks count = `____` count, and so on), and writes `src/generated/content.json`. The build fails on any error.

## Python runtime
### Worker (`src/python/worker.ts`)
- Loads Pyodide from `/pyodide/` (same origin, precached), then writes `seed/data/*` to `/home/pyodide/data/` and `voicelab.py` + `harness.py` to `/home/pyodide/`. It then imports `harness`. The seed files are kept in `/opt/pyreps-seed/` and copied back into `/home/pyodide/` before every run, so one run can't damage them for the next.
- Message protocol (all messages carry a `runId`):
```ts
// main -> worker
{ type: "init" }
{ type: "run", runId, code: string, mode: "plain" | "test", tests?: string, files?: Record<string,string> }
// worker -> main
{ type: "ready", pythonVersion }
{ type: "init-error", message }                     // Pyodide failed to load
{ type: "stdout" | "stderr", runId, text }          // streamed, batched
{ type: "done", runId, ok: boolean, error?: { type, message, traceback, line? }, checks?: { passed: boolean; failures: string[] }, ms }
```
- Each run starts like a new process: a fresh `__main__` module with `__name__ = "__main__"`, and the harness resets user-imported modules, files, cwd, `os.environ`, `sys.argv`, logging and `sys.stdout`. The cwd is `/home/pyodide`. Project files are written to `/home/pyodide/project/` before the run.
- Tracebacks: show only the user's frames, with the filename shown as `main.py` and line numbers matching the editor.
- `SystemExit` with code 0 or None counts as success. Any other code is reported as "exited with code N", not as a crash.
- **Pyodide limits** (found in Phase 1): no threads, no processes (`subprocess.run` raises `OSError`), `asyncio.run()` fails because the entry point is synchronous, `hashlib.pbkdf2_hmac` is missing, and `input()` raises at once. See CONTENT.md rule 10.
- **Lock after load**: the page CSP doesn't apply inside a same-origin worker (it uses its own response headers, and GitHub Pages sends none). So once Pyodide has loaded, the worker deletes network and storage APIs (`fetch`, `XMLHttpRequest`, `WebSocket`, `indexedDB`, `caches`, `importScripts`, `navigator`, …) and blocks code-from-text (`eval`, `Function`, string timers), so `import js` can't reach them. This is a JavaScript lock, not one the browser enforces.

### Client (`src/python/client.ts`)
- Singleton: `python.run(code, opts): Promise<RunResult>`.
- **Timeout 5 s**: call `worker.terminate()`, then spawn a new worker and re-init (fast once Pyodide is in the HTTP cache), and resolve with `{ ok:false, error:{ type:"Timeout" } }`. Don't use `SharedArrayBuffer` interrupts: GitHub Pages can't send the COOP/COEP headers they need.
- Start the worker on app load (warm-up). Expose `status: "loading" | "ready" | "restarting" | "error"` to the UI.

### Test harness (`src/python/harness.py`)
- Provides `check(cond_or_callable, msg)` and `report()` (same idea as the course): it collects failures and never raises.
- For `write` cards the worker runs `starter-edited-by-user` + `"\n"` + `tests` wrapped in try/except (so a crashing test becomes a failure message) + `report()`. If the user's code itself raises before the tests run, the result is `ok:false` with the traceback.
- **Never** run user code on the main thread, and never `eval` anything outside the worker.

### `python/voicelab.py`
- `DATA = Path(__file__).parent / "data"` (it works in Pyodide and with CPython in the validator)
- `load_cdrs() -> list[dict]` reads `data/cdrs.csv` with `csv.DictReader`.
- `read_log() -> list[str]`.
- `fake_kubectl(*args) -> str` returns `pods.json` text, and `fake_prometheus(query, **kw) -> str` returns `prom.json` text.
- Docstrings say clearly that these stand in for `subprocess.run(["kubectl", ...])` and `requests.get(...)`.

## Grading (`src/cards/grading.ts`, pure functions)
- **predict**: normalise both strings (strip trailing whitespace per line, strip trailing newlines, `\r\n`→`\n`) and compare exactly. The input field shows hints for multi-line answers. If `options` exist, it renders as multiple choice instead.
- **mcq**: index equality.
- **fill**: each blank equals its answer. With several blanks, all must be right; partially right counts as wrong but highlights which ones.
- **spot_bug**: tapped line === `bug_line`. Then show the diff to `fixed_code`.
- **parsons**: the user's sequence of `(line text without leading spaces, indent level)` must equal the expected sequence. Distractors placed in the answer make it wrong. Indent is set by ← / → buttons on a placed line (levels 0–4).
- **write**: the harness result `checks.passed`.

## Spaced repetition (`src/srs/`)
- One FSRS card state per content card id, stored in IndexedDB. Use `ts-fsrs` defaults with `request_retention: 0.9` and `maximum_interval: 180` days.
- **Automatic rating** (no self-rating buttons):
  - correct on the first try, no hint, within the time budget (predict/mcq/fill/spot_bug 45 s, parsons 90 s, write 240 s) → `Good`
  - the same but faster than 40% of the budget, and the card has already been reviewed at least twice → `Easy`
  - correct after one retry, or after using the hint → `Hard`
  - wrong twice, or "Show answer" → `Again` (the card is re-queued once at the end of today's session)
  - `write` cards: a failed Check doesn't end the card (a typo shouldn't). It only sets the result: 0 failed Checks and no hint → first try, 1 failed Check or the hint → retry (`Hard`), 2 or more → `Again`. Run is free. Errors from the runtime itself (not ready, crashed) don't count.
- The user can always tap "I knew this" / "I guessed" after the reveal, to change Good⇄Hard only. Keep it small and optional.
- **Planner** (`planner.ts`): `due = cards where due <= endOfToday`, sorted by due (oldest first), capped at `maxReviews`. Then add `newPerDay` new cards from unlocked topics in course order (level 1 before 2 before 3). Interleave so the same topic doesn't come twice in a row when possible. Put a `write` card at most every 4th position, to keep the session thumb-friendly.
- "Practise topic" mode uses the same card components but only updates FSRS for cards that are actually due (otherwise it just records attempts).
- A day starts at 04:00 local time (Anki convention), so late-night sessions count for the right day.

## Persistence (`src/db/db.ts`, Dexie)
```ts
db.version(1).stores({
  reviewStates: "cardId, due, state",          // ts-fsrs Card + cardId
  reviewLog:    "++id, cardId, at, rating",     // for stats and undo
  attempts:     "++id, cardId, at",             // practice-mode attempts
  projects:     "projectId",                    // { projectId, stepIndex, files: Record<string,string>, updatedAt }
  kv:           "key"                           // settings, playground code, streak cache, schemaVersion
});
```
- At startup, call `navigator.storage.persist()` and show the result in Settings. Home Screen web apps on iOS keep their own storage, which is why the app tells the user to install it.
- Backup: export everything as `pyreps-backup-YYYY-MM-DD.json` through the share sheet or a download, and import with confirmation (it replaces the data). Include `schemaVersion` and write migrations.
- Content updates: when a card id disappears from content, keep its state but ignore it. When a card's text changes, keep its state; a changed `id` means a new card.

## Mobile editor (`components/CodeEditor.tsx`, `SymbolBar.tsx`)
- A plain `<textarea>` with `autocapitalize="off" autocorrect="off" spellcheck="false" inputmode="text"`, monospace 16 px (iOS Safari zooms into inputs with smaller text), ligatures off, `tab-size: 4`, horizontal scroll (no wrapping), line numbers in a gutter.
- Don't use CodeMirror or Monaco in v1. They're heavy and fragile on the iOS keyboard. Syntax highlighting is only needed for read-only code (CodeView), with a tiny tokenizer or Prism with just Python.
- **SymbolBar**: sticky above the keyboard. Keys block `mousedown` (not `pointerdown`, which cancels the click on touch) so the editor keeps focus. Position it with `visualViewport` resize/scroll events so it stays visible when the keyboard opens. Keys: `⇥` `(` `)` `[` `]` `{` `}` `:` `"` `'` `=` `_` `*` `.` `,` `#` `←` `→` `↶`. Typing an opening bracket inserts the pair and puts the caret between them.
- Enter after a line ending in `:` adds 4 spaces of extra indent. Backspace at an indent removes 4 spaces.
- The undo button keeps its own small undo stack (iOS shake-to-undo isn't reliable).

## PWA and offline
- `vite-plugin-pwa` (Workbox `generateSW`): precache the app shell, `content.json`, `seed/data`, fonts and **the Pyodide files** (`pyodide.asm.mjs`, `pyodide.asm.wasm`, `python_stdlib.zip`, `pyodide-lock.json`, `pyodide.mjs`). Raise `maximumFileSizeToCacheInBytes` to cover the wasm file.
- Manifest: `display: standalone`, `start_url` and `scope` set to the Pages base path, `theme_color` and `background_color` for both colour schemes, apple-touch-icon 180 px.
- Show an update toast when a new service worker is waiting ("New version, tap to reload").
- Set `base` in `vite.config.ts` to `/pyreps/` (the GitHub Pages repo path), and use the router's `basename`. **HashRouter** avoids 404s on GitHub Pages deep links.

## Styling direction
- Mobile-first, one column, max width 640 px on desktop. Bottom tab bar, large primary buttons in the thumb zone.
- Calm, high-contrast palette with semantic colours for right/wrong. Both light and dark (`prefers-color-scheme`).
- Body font: Atkinson Hyperlegible (readability for a non-native reader). Code font: JetBrains Mono with ligatures **off** (`font-variant-ligatures: none`). Self-host fonts so they work offline.
- Respect `prefers-reduced-motion`. No hover-only affordances. Feedback is visual and textual (iOS Safari has no vibration API).
- Code blocks scroll horizontally. Never let the page body scroll sideways.

## Security notes
- All user code runs inside the worker's WebAssembly sandbox. The worker has no access to the DOM, and after load no access to IndexedDB or the network.
- Content is trusted (it's in the repo), but render it as text. No `dangerouslySetInnerHTML`, except for the syntax highlighter output built from escaped tokens.
- CSP via a `<meta http-equiv>` tag: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'`. The page doesn't need `'unsafe-eval'` (checked in Phase 1). Pyodide uses `eval` inside its worker, where this CSP doesn't apply; see "Lock after load".
- No third-party requests at runtime.

## Deployment
- `.github/workflows/deploy.yml`: on push to `main`, run `npm ci`, `python3 scripts/validate_content.py`, `npm run build` and `npm test`, then deploy `dist/` with `actions/deploy-pages`.
- `ci.yml` runs the same checks on pull requests, plus Playwright with an iPhone profile.
- Installing on the phone: open `https://<user>.github.io/pyreps/` in Safari, tap Share, then **Add to Home Screen**. Open it once online so the Python runtime downloads and caches.
